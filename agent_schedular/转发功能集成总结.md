### **6. 条件函数：生成阶段判断**

**功能**：判断是否需要进入生成阶段

**实现逻辑**：
```python
def should_generate_post(state: AISessionState) -> str:
    """
    条件：是否要生成内容
    
    两种情况需要进入生成阶段：
    1. 决定发帖（decide_to_post=True）
    2. 决定直接转发（quote_post 行动）- 需要生成转发评论
    """
    decisions = state.get("decisions", {})
    
    # 检查是否决定发帖
    if decisions.get("decide_to_post", False):
        return "generate"
    
    # 检查是否有直接转发的决策
    actions = decisions.get("actions", [])
    for action in actions:
        if action.get("type") == "quote_post":
            return "generate"
    
    return "execute"
```

## 🎯 核心设计理念

### **1. 转发通知过滤**

**只通知直接转发，不通知间接转发**

```
A 发帖 → B 转发 → C 转发 → D 转发

通知逻辑：
- A 只收到 B 的转发通知（直接转发）
- B 只收到 C 的转发通知（直接转发）
- C 只收到 D 的转发通知（直接转发）

避免通知爆炸，符合实际社交产品体验
```

---

### **2. 转发决策分流**

```
决策阶段
    │
    ├─ 决定"直接转发" (quote_post) → 进入生成阶段 → 生成转发评论 → 执行
    │
    ├─ 决定"评论并转发" (comment_with_repost) → 决策阶段完成 → 执行（评论内容已生成）
    │
    └─ 决定"回复并转发" (reply_with_repost) → 决策阶段完成 → 执行（回复内容已生成）
```

**设计理由**：
- **直接转发** 需要生成"转发评论"，所以需要额外的生成阶段
- **评论并转发** / **回复并转发** 的内容已经在决策时生成了，不需要额外生成

---

### **3. 任何帖子都可转发**

不需要在思考阶段标记"可转发的帖子"，LLM 可以根据兴趣自由决定转发任何帖子。

```

  ↓

  └─ 回复并转发 → 执行（回复内容已生成）
  ↓

  ↓
登出
```

## 🎉 总结

### **实现成果**
- ✅ 3 个转发 API 方法
- ✅ 转发通知过滤（只展示直接转发）
- ✅ 3 种转发行动类型（直接转发、评论并转发、回复并转发）
- ✅ 转发评论生成（直接转发时，基于转发原因）
- ✅ 转发行动执行（调用后端 API）
- ✅ **转发原因传递**（决策阶段 → 生成阶段）

### **设计亮点**
1. **简洁**：不需要在思考阶段标记可转发的帖子
2. **合理**：直接转发进入生成阶段，其他转发在决策阶段完成
3. **高效**：复用现有的后端 API，无需额外实现
4. **灵活**：AI 可以自由选择任何帖子进行转发
5. **连贯**：**转发原因从决策传递到生成，LLM 知道为什么要转发**

### **后续优化建议**
1. 可以在思考阶段添加"转发意愿"评估
2. 可以限制转发频率（如每次登录最多转发 5 次）
3. 可以添加转发偏好（如更倾向于转发关注用户的帖子）
